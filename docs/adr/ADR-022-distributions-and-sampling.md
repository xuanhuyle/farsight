# ADR-022 — Distribution families, parameterization, and sampler stream stability
**Status:** Accepted 2026-08-28 (MVP commitment; see Revisit triggers)
**Date:** 2026-08-26
**Deciders:** FarSight founding engineering
**Plan reference:** FARSIGHT_FOUNDATION_PLAN.md §9 (the `Distribution` object, two-loop propagation, correlation groups), §11 (planner purity, seeding, sampling ownership D11), §12 (determinism rules), §2 tripwire 4 (seeded LHS/MC only), §7 (decimal-string magnitudes), decisions D9 and D11
**Related ADRs:** ADR-000 (the escape-hatch tokens and the `review_signoffs` rows this record's checklist items land in), ADR-001 (whether `(experiment_hash, run_index) -> spec_hash` survives as a pure derivation is decided here), ADR-004 (the `Distribution` object this record fills in, and the outer scan and inner hypercube whose designs this record pins), ADR-005 (the seed authority: this record consumes its streams and takes the bit generator's raw words as the only stable primitive), ADR-006 (once the library axis is removed, what remains is exactly the tier boundary this record inherits), ADR-008 (physical parameterization and the adapter conversion-table pattern reused for library boundaries), ADR-013 (assembles the import-linter file this record's contract ships in), ADR-014 (the `scipy` version range that creates the forcing question, and the dependency status this record changes the justification for), ADR-017 (sorted topology-path order, which fixes draw order), ADR-019 (the container that pins the libm this record's residue rests on)

## Context

The forcing question is narrow: **what guarantees that the same seed produces the same physical value in 2029?**

ADR-005 answers half of it rigorously. A root seed plus `SeedSequence(entropy, spawn_key=(run_index, stream_id))` plus Philox gives an O(1)-addressable bit stream, NumPy's stream-compatibility policy covers the named bit generator, and the `generate_state` words are archived per run. Nothing about that half is in question.

The other half is the transformation from those bits to a Rayleigh sample, and it is currently owned by nobody. Two library facts decide the shape of the answer. SciPy does not guarantee stream stability for `rvs` across versions - the algorithm behind a distribution's sampler may change - and ADR-014 pins `scipy>=1.11,<2`, a range resolved by the lock rather than an exact version. NumPy's stream-compatibility policy covers *bit generators*; `Generator` methods such as `normal`, `permutation` and `integers` are explicitly not covered by the same guarantee, so consuming them is the same exposure one layer down.

That collides with an accepted claim. ADR-001 rule 5 states that `(experiment_hash, run_index) -> spec_hash` is a derivation and not a database join, and its own confidence table already carries a 0.75 row anticipating that this record might force the sentence to be restated. ADR-005 says replay consumes the archive and does not re-derive. Both cannot be fully true across a library bump: the archive would replay fine while the derivation quietly produced different values, and `--verify-derivation` would fail with nothing in the environment fingerprint obviously pointing at the cause. ADR-014's Context names exactly this failure: we would be debugging FMA and libm differences while the actual cause is a SciPy minor version.

Two smaller things are undecided in the same area and are forced at the same moment. The permitted family list does not exist, so week 3-4's belief tagging has no vocabulary. And the parameterization convention does not exist, which matters because SciPy's `loc`/`scale` convention is a classic silent factor-error source: `truncnorm` takes its bounds in standardized units, and `lognorm`'s `scale` is `exp(mu_log)` rather than a mean - the exact class of defect ADR-008 exists to prevent at engine boundaries, arriving instead through a statistics library.

What breaks concretely: a SciPy patch release silently changes every aleatory draw in every replanned campaign, presenting as a golden-hash break with no attributable cause. The plan's flagship pattern - `Aleatory(rayleigh, sigma=EpistemicInterval(...))` - is the first thing built in week 3, so the exposure starts on day one of the first pipeline.

## Decision

**1. FarSight consumes raw 64-bit words from the Philox bit generator and implements every transformation itself.** The only third-party surface in the sampling path is the bit generator whose stream NumPy's policy covers and whose words ADR-005 already archives. Everything above it - uniforms, unbiased bounded integers, permutations, inverse CDFs, and the Gaussian copula factor - is FarSight source.

```python
# src/farsight/uncertainty/bits.py
def words(bg) -> Iterator[int]: ...        # Philox raw 64-bit words, the one primitive
def unit_uniform(w: int) -> float:         # 53-bit construction, exact and portable
    return (w >> 11) * (1.0 / 9007199254740992.0)     # 2**-53, no libm, no rounding surprise
def bounded_int(bg, n: int) -> int: ...    # unbiased by rejection; declared, tested
def fisher_yates(bg, n: int) -> list[int]: ...        # integer-valued, therefore exactly portable
```

`unit_uniform` returns a value in `[0, 1)`; the inverse CDFs take `1 - u` where they need `(0, 1]` so that no draw can evaluate an inverse CDF at exactly zero or one.

**2. The permitted families are exactly those whose inverse CDF we implement and property-test.** The MVP list is closed and small:

| family | parameters (physical, with units) | inverse CDF |
|---|---|---|
| `uniform` | `low`, `high` | `low + (high - low) * u` |
| `normal` | `mu`, `sigma` | `mu + sigma * ndtri(u)` |
| `truncated_normal` | `mu`, `sigma`, `low`, `high` | inverse over the truncated support, in physical units |
| `lognormal` | `mu_log`, `sigma_log`, `reference_unit` | `reference_unit * exp(mu_log + sigma_log * ndtri(u))` |
| `rayleigh` | `sigma` | `sigma * sqrt(-2 * log(1 - u))` |

`ndtri` is the normal quantile function, implemented in FarSight from a published rational-approximation algorithm with a stated accuracy bound. UNVERIFIED - the specific algorithm is chosen at implementation time; the requirement fixed here is that it be published and citable, implemented in FarSight source, and tested to a declared relative-error bound against SciPy's `ndtri` at the pinned version.

Adding a family is a schema change requiring an inverse-CDF implementation, its accuracy suite, and a named parameter that needs it. Families are never added speculatively. Three exclusions are deliberate and stated:

- **`triangular` is excluded.** It is the shape most often used to dress a three-point expert estimate as a distribution, and ADR-004 already provides `EpistemicInterval` for exactly that case. Making the honest representation easier than the laundering one is the point.
- **`beta` and every other family without an elementary inverse CDF are excluded.** Inverting the regularized incomplete beta is real numerics we are not writing in week 3, and taking it from a library would make the purity claim per-family rather than uniform. Bounded fractions use `truncated_normal` in the MVP. `beta` is the named first candidate for addition.
- **Discrete families are excluded.** A discrete inverse CDF has ties, which interacts with LHS stratification and with the `unit_uniform` boundary in ways that need their own decision. Counting statistics such as SNSPD photon counts are internal mathematics of the link-chain engine on the raw SI float64 core, not a parameter `Distribution`, so nothing in the flagship needs one.

**3. Parameters are physical, named and dimensioned; `loc` and `scale` appear nowhere.** Every parameter is a `Quantity` (decimal string plus unit, ADR-001) or an epistemic `Belief` (ADR-004's hyperparameter pattern). The mapping to any library's parameterization is an explicit conversion table in the same shape ADR-008 mandates for engine adapters, because a statistics library is an engine boundary and should be treated as one:

```python
# src/farsight/uncertainty/library_map.py  -- used by the TEST ORACLE only, never in the truth loop
SCIPY_MAP = (
    LibParam(family="rayleigh",         our=("sigma",),
             lib="rayleigh", kwargs=lambda p: {"loc": 0.0, "scale": p.sigma}),
    LibParam(family="lognormal",        our=("mu_log", "sigma_log", "reference_unit"),
             lib="lognorm",  kwargs=lambda p: {"s": p.sigma_log, "loc": 0.0,
                                               "scale": math.exp(p.mu_log)}),
    LibParam(family="truncated_normal", our=("mu", "sigma", "low", "high"),
             lib="truncnorm", kwargs=lambda p: {"a": (p.low - p.mu) / p.sigma,      # standardized
                                                "b": (p.high - p.mu) / p.sigma,     # standardized
                                                "loc": p.mu, "scale": p.sigma}),
)
```

The two rows that carry the trap are written out because they are the trap: `lognorm`'s `scale` is `exp(mu_log)` and not a mean, and `truncnorm`'s bounds are standardized. `mu_log` and `sigma_log` are dimensionless and are defined on the natural logarithm of the quantity expressed in `reference_unit`, which is required, because the logarithm of a dimensioned quantity is not defined without one. Support constraints (`sigma > 0`, `low < high`, `high > low` after unit normalization) are validated at freeze, not at draw time.

**4. A drawn value becomes a decimal string by the shortest round-tripping decimal.** The planner writes concrete values into RunSpecs (ADR-005), and those are hashed, so the float-to-string step is part of identity and cannot be left to a formatter. The rule: the shortest decimal string that round-trips to the same binary64, normalized into ADR-001's magnitude grammar (explicit exponent sign, lowercase `e`, no leading zeros). It is not rounded to a declared precision; see the rejected Option 4.

**5. The sampling design carries its own `design_seed`, inside the frozen `SamplingPlan`.** ADR-004 and ADR-005 both describe the outer epistemic scan as a deterministic Latin hypercube with no RNG. A Latin hypercube is only deterministic once its permutations are pinned, so this record pins them: the frozen `SamplingPlan` carries a 128-bit `design_seed` as a decimal string, and the outer permutations come from `SeedSequence(entropy=design_seed, spawn_key=(0xD5, 0))` through the same Fisher-Yates in item 1.

`0xD5` is the design-scope tag and is never a `run_index`. Every design-scoped key has the shape `(0xD5, scope, ...)`: scope `0` is the outer design, scope `1` an inner design. The tag exists because the obvious spelling, `spawn_key=(0, 2)`, is bit-for-bit ADR-005's `stream_rng(root_seed, run_index=0, stream_id=2)` - ADR-005 permits a root seed to be supplied explicitly for replication studies, and a study supplying one value for both `root_seed` and `design_seed` would hand run 0's `sampler_internal` bookkeeping and the whole outer design the same words. ADR-005 is the authority on stream derivation and carries the matching validator.

The inner design is pinned the same way and at the same level of aggregation. Per outer point, the inner LHS stratum assignment is `SeedSequence(entropy=design_seed, spawn_key=(0xD5, 1, outer_index))` through the same Fisher-Yates; it is integer-valued and therefore bitwise portable. Run `(outer_index, inner_index)` reads its stratum from that design and maps the stratum to a physical value using the uniforms it draws from its own `aleatory_draws` stream. The design is a pure function of the frozen `SamplingPlan`, so no inner value depends on run order or worker count.

This is a clarification of both records rather than a contradiction, and the property each needs is preserved exactly. No outer coordinate depends on the campaign root seed, on the order the grid was generated in, on run order, or on worker count; the design is a pure function of the frozen `SamplingPlan` and therefore of `experiment_hash`, and it is identical on every re-plan. That was ADR-005's stated reason for wanting the outer loop RNG-free, and it still holds. The design is also integer-valued - permutations of stratum indices - so it is bitwise identical on every platform; only the inverse-CDF evaluation that maps a stratum to a physical value involves a float.

Outer points are generated in one declared order and concatenated: the LHS points in design order, then the interval vertices in the `oat_screening_rank` order ADR-004 declares, then the Cartesian product with exhaustive `EpistemicSet` enumeration. `outer_index` is the position in that concatenated order. Coincidences are not de-duplicated: a vertex that lands on an LHS stratum midpoint stays, because removing it would make `n_outer` depend on a numerical coincidence. Total outer points are therefore `(n_lhs + n_vertices_selected) * prod(|set_i|)`, and `vertex_cap` binds on the interval coordinates only - three three-member `EpistemicSet`s multiply the whole thing by 27 with no cap anywhere, which is stated in Consequences rather than discovered in week 5.

**6. `sampling_scope` maps to draw counts, not to a separate stream.** Draw order within a run stays exactly ADR-005's: iterate parameters in sorted topology-path order on stream 0. Where a parameter is stratified by the inner design of decision 5, that uniform positions the value *within* the stratum the design assigned to `(outer_index, inner_index)` — the design supplies the stratum, the run's own stream supplies the offset inside it. What a parameter's scope changes is how many values it draws for that run. `per_run` draws one. A group scope `{"per_group": "<name>"}` draws one per member of that `ScenarioEnumeration`, in member order (ADR-027, which retires the earlier `per_pass` spelling and gives it the referent it lacked — no record defined how a scenario declared a pass). `per_experiment` draws once at the lowest `run_index` of its outer point and the value is copied into every RunSpec at that outer point - once per outer point rather than once globally, because `Aleatory.at(point)` (ADR-004) may resolve an epistemic hyperparameter differently at each outer point, so an experiment-scoped quantity is one realization per epistemic world. Every run has its own independent stream via its own `spawn_key`, so copying consumes no words and cannot shift any other parameter's draw.

**7. Correlation groups use a FarSight Cholesky, computed at plan time and archived.** ADR-004's Gaussian copula needs a factor of the PSD-validated rank correlation matrix. LAPACK's result depends on the BLAS vendor and on runtime CPU dispatch, which is a portability variable the environment fingerprint captures poorly. Correlation groups have a handful of members, so a textbook Cholesky in a declared elimination order costs nothing and uses only `+`, `-`, `*`, `/` and `sqrt`, all of which IEEE-754 specifies exactly. The factor is computed once per group at plan time and archived in `campaign.json` as decimal strings, so an auditor re-deriving a draw needs no linear algebra library at all. PSD validation and the rank-matrix semantics remain ADR-004's.

**8. The sampling path uses scalar `math.log` and `math.exp`, never NumPy's vectorized ufuncs.** NumPy's SIMD loops dispatch on runtime ISA, so a vectorized `log` can differ between an AVX2 and an AVX-512 runner *inside the same container image* - which is the variable ADR-006 handles by putting the CPU ISA feature set into the Tier-A predicate. Scalar libm calls remove one axis of that for free: draws are per-parameter, not per-sample-of-a-channel, so a 10,000-run campaign with a dozen aleatory parameters is of order 10^5 scalar calls and the cost is not measurable.

**9. What this buys ADR-001, stated exactly.** After items 1 through 8, the sampling path depends on: Philox raw words (covered by NumPy's bit-generator policy and archived anyway), IEEE-754 arithmetic including correctly-rounded `sqrt`, and libm's `log` and `exp`. No SciPy, no `Generator` methods, no LAPACK, no `qmc`. The derivation is therefore pure with respect to every library FarSight depends on, and its float-level reproducibility is governed by ADR-006's tiers exactly like every other floating-point computation in the system.

ADR-001's rule-5 caveat currently reads that "pure derivation" means inside a pinned environment until this record fixes it. It should be restated as: **`(experiment_hash, run_index) -> spec_hash` is a pure derivation in FarSight code; its bit-level reproducibility is Tier A in the reference container and Tier B across platforms, on the same footing as every other float in the system, and the archived draws (ADR-005) remain what makes replay independent of re-derivation.** ADR-001's confidence row anticipating a demotion does not fire; the sentence narrows rather than weakens.

One consequence must be said plainly rather than left implied. Cross-platform, a drawn value may differ in the last unit in the last place, which changes its decimal string and therefore the `spec_hash`. That is harmless for replay, which reads `runspec_<i>.json` from the package and never re-plans (ADR-005, AT-1). It is not harmless for ADR-005's revisit trigger, which treats a cross-platform `--verify-derivation` failure as evidence the archive is doing real work: under this decision a last-ULP cross-platform difference is *expected* and is a Tier-B observation, not a finding. That trigger should be re-keyed to same-container mismatches, or to differences exceeding a declared ULP bound. Flagged here rather than silently diverged; the row belongs to ADR-005.

## Options considered

### Option 1 — Use SciPy `rvs` and `qmc` and pin SciPy to an exact version — REJECTED
The standard, correct answer. SciPy's distributions are validated far past anything we will write, `qmc.LatinHypercube` is a maintained implementation of the exact design we need, an exact pin makes the stream reproducible for that pin, and `environment/fingerprint.json` records it. Essentially every Monte Carlo code in the industry does this, including Basilisk's own MC Controller. Rejected on three grounds. An exact pin is a maintenance dead end: no patch upgrade, security or otherwise, without re-golding every campaign, and ADR-014 deliberately chose ranges for everything else. It does not help the auditor, who would have to install that exact SciPy to check a derivation. And the failure mode is silent: SciPy documents no `rvs` stream guarantee, so a version drift changes physical values and presents as a physics regression. Conceded: our own implementations will be less accurate than SciPy's in the extreme tails, and we state the bound rather than hide it.

### Option 2 — Use SciPy's `ppf` with our own uniform stream — REJECTED, and this is the closest option
This deserves the hardest steelman because it is very nearly right. Inverse-CDF sampling from our own uniforms removes the `rvs` instability entirely, and that is where most stream instability actually lives: whether a normal draw comes from Ziggurat, Box-Muller or the polar method is an algorithm choice that can change, whereas `ppf` is a mathematical *function* whose value is stable up to floating-point accuracy. SciPy's `ppf` implementations are far better tested than ours will be, especially in tails, and we would write and maintain zero numerics. It is cheaper, more accurate, and defensible to a numerics reviewer.

Rejected on a narrow ground, and the ground is change control rather than accuracy. Accuracy improvements to special functions *are* value changes, they land in patch releases as ordinary bug fixes, and a last-ULP change in `ndtri` moves a decimal string, moves a `spec_hash`, and presents as a golden-hash break with no attributable cause - ADR-014's stated nightmare, arriving through the one dependency whose change would look most like physics. Our own implementation changes only when we change it, and when we do, ADR-006's `EXPECTED-CHANGE` re-golding procedure applies with a written reason and a second-dev review. We are buying the right to know when a number moved, and paying for it in tail accuracy.

### Option 3 — Accept the archive as sole truth and demote ADR-001's derivation claim — REJECTED
Free, and already half-implemented: ADR-005 archives every derived word and every drawn value, and replay reads the archive, so replay works today regardless of what SciPy does. Demoting one sentence in ADR-001 costs nothing operationally, and one can argue the derivation was always a nicety while the archive is the product. Rejected because the derivation is what makes the planner's purity *checkable*. An archive can only be checked against itself: if a planner defect produced wrong draws, nothing in a package would reveal it, because the wrong draws are exactly what the archive records. The derivation is also what makes AT-7's standalone re-execution arithmetic rather than a database restore, which is ADR-001's own stated reason for content addressing. Conceded honestly: this is the option we would take under schedule pressure, and it is the pre-written fallback if the week-3 accuracy suite fails - see the confidence row.

### Option 4 — Quantize each drawn value to a declared number of significant figures — REJECTED
Attractive at first: it would make the RunSpec identical across platforms almost always, and it fits ADR-001's rule that significant figures are an engineering claim. Rejected because "almost always" is the worst possible property for an identity function. Last-ULP differences would cross a rounding boundary for some small fraction of draws, so a campaign in which 3 of 10,000 values differ produces a `spec_hash` mismatch that is indistinguishable from tampering, at a rate that depends on the values themselves.

### Option 5 — Parameterize hashed documents in the library's `loc`/`scale` convention — REJECTED
Zero conversion code and therefore zero conversion bugs, documents that map one-to-one onto the library every reviewer knows, and instant legibility for anyone fluent in SciPy. Rejected because `loc` and `scale` are dimensionless library conventions: a hashed physical document would carry a number with no unit and no physical name, which ADR-001 rule 2 forbids and ADR-008 exists to prevent. `truncnorm`'s standardized bounds are the exact silent-factor trap, and putting it in the hashed record would make the trap permanent.

### Option 6 — FarSight owns uniforms, inverse CDFs, permutations and the Cholesky, over Philox raw words — CHOSEN
It reduces the sampling path's third-party surface to the one primitive whose stability is documented and already archived, keeps ADR-001's derivation claim standing with a narrower and honest caveat, and moves the remaining non-determinism onto the libm and ISA axes that ADR-006 and ADR-019 already govern. It costs real numerics we have to write, test and defend.

## Consequences

**Buys us:** an aleatory draw that is a function of FarSight source and IEEE-754, so a value that moves has a cause we can name. ADR-001 rule 5 survives as written, with the caveat narrowed rather than the claim demoted. `--verify-derivation` (ADR-005) becomes a meaningful same-container check rather than a library-version detector. The parameterization is physical and dimensioned end to end, so the `truncnorm`-bounds and `lognorm`-scale error classes cannot reach a hashed document. And both designs — the outer scan and the inner hypercube at each of its points — are integer-valued and pinned by a `design_seed` inside the frozen plan, which makes "the sampling design is deterministic" a checkable statement rather than an assertion.

**Costs us:** we now own numerics. Five inverse CDFs, a normal quantile approximation, an unbiased bounded-integer routine, Fisher-Yates, and a Cholesky, each with an accuracy suite and a stated bound, in weeks 3-5 when the schedule is tightest. Tail accuracy will be worse than SciPy's and we have to publish the bound rather than mention it. The permitted family list is short enough that a parameter needing a bounded fraction gets `truncated_normal` instead of `beta`, and a parameter needing a count-valued draw cannot be expressed at all. SciPy remains a dependency for the test oracle and for whatever else the set needs it for, so the trust surface does not shrink by as much as the truth loop does. And a `design_seed` is one more required field in a frozen document, which is an identity change to every `SamplingPlan`.

**Forecloses:** any family whose inverse CDF we are unwilling to implement, which today means the entire bounded-fraction and discrete worlds, and tomorrow means that a customer arriving with a fitted empirical distribution or a kernel density estimate cannot express it without a schema change - a real limitation for anyone whose in-house process hands over a sampled dataset rather than a parametric family. It also forecloses using `scipy.stats.qmc` for anything in the truth loop, so if we later want Sobol or a scrambled sequence for the outer design we implement direction numbers ourselves or change this record. And because the sampling path is our code, **a defect in our inverse CDF is indistinguishable from physics until the accuracy suite catches it** - we have moved a class of risk from a library maintained by hundreds of people into a module maintained by three, and the accuracy suite is the only thing standing there.

## Enforcement

1. `tests/unit/test_inverse_cdf_accuracy.py` (**first green by week 3**) - each implemented inverse CDF is compared against SciPy's `ppf` at the pinned version over a dense grid including both tails, and must sit inside a declared relative-error bound recorded in the module docstring; Hypothesis properties assert monotonicity in `u`, correct behaviour at the support boundaries, and that `cdf(icdf(u))` returns `u` to the declared bound. SciPy is the oracle here and appears in tests only.
2. `tests/unit/test_sampler_stream_stability.py` (**first green by week 3**) - a checked-in golden table mapping `(root_seed, run_index, family, params)` to the exact decimal-string draw, for every permitted family and for a set of parameter values including boundary cases. CI fails on any change. This is the actual regression tripwire for the whole record, and re-golding it requires an `EXPECTED-CHANGE` note under ADR-006's policy.
3. import-linter contract `no_sampler_libraries` (owned here; assembled into the single `.importlinter` file by ADR-013; **first green by week 2**) - `farsight.uncertainty` and `farsight.experiments` may not import `scipy`, `scipy.stats`, `scipy.stats.qmc`, `scipy.linalg`, `numpy.linalg` or `numpy.random.mtrand`.
4. `PARTIALLY MECHANIZED: DIST-1` - `tests/unit/test_sampling_path_isolation.py` (**first green by week 2**). An AST scan asserts that under `farsight/uncertainty/` and `farsight/experiments/` the only `Generator`/bit-generator attribute reached is the declared raw-word accessor, and that `loc` and `scale` appear as identifiers nowhere in `src/farsight/` outside `library_map.py`. Item 3's half is sound, because imports are decidable; this half is not, because an attribute reached through `getattr`, a dynamic import or an aliased module is invisible to an AST scan and "this function calls no library sampler" is not decidable in general. The residue is narrowed the way ADR-005 narrows `SEED-1`: `getattr`, `eval`, `exec` and `importlib` are banned outright in those two packages, which converts most of the unsound class into a sound one by constraining the input. Review-checklist item **DIST-1** - *"does any new third-party call in the sampling path transform random bits into a value, and if so is it in the test oracle rather than the truth loop?"* - carries the rest and lands in `review_signoffs` (ADR-000).
5. `tests/unit/test_distribution_parameterization.py` (**first green by week 2**) - every family's parameter names are exactly the declared set under `extra="forbid"`; every parameter's unit is dimensionally consistent with the sampled quantity's declared unit; `lognormal` without `reference_unit` fails at construction; support constraints are validated at freeze and not at draw time; and every row of `SCIPY_MAP` round-trips against an independently written expected value, in the ADR-008 conversion-table pattern.
6. `tests/unit/test_lhs_design_determinism.py` (**first green by week 3**) - the same frozen `SamplingPlan` yields a byte-identical outer design, and a byte-identical inner design for every `outer_index`, in the same order, across two processes and two platforms. Both designs are integer-valued, so this is a bitwise assertion on every platform rather than a tolerance.
7. `tests/unit/test_outer_design_root_seed_independence.py` (**first green by week 3**) - the outer design, and every inner design, is byte-identical under two different campaign root seeds with the same `design_seed`, and changing `design_seed` changes both. This is the mechanical form of ADR-004's and ADR-005's "the outer scan carries no RNG" property. That the design-scoped key space is disjoint from ADR-005's run-index key space is asserted by `test_seed_derivation` (defined in ADR-005), not here.
8. `tests/unit/test_drawn_value_encoding.py` (**first green by week 2**) - a Hypothesis property over generated float64 values asserting that the decimal string is the shortest round-tripping representation, that it parses back to the identical binary64, and that it satisfies ADR-001's magnitude grammar; and that no rounding-to-significant-figures code path exists.
9. `tests/unit/test_cholesky_determinism.py` (**first green by week 4**, when correlation groups first appear in a design) - the FarSight factorization matches a LAPACK factorization of the same matrix to a declared bound, reproduces bitwise across two processes and two platforms, and the archived decimal-string factor in `campaign.json` reconstructs the matrix to that bound.
10. `ci-worker-order-invariance` (defined in ADR-006; **first green by week 5**) - already required elsewhere, and it is the end-to-end check that no part of this record's sampling path acquired an order dependence.
11. `NOT MECHANIZABLE: DIST-2` - whether the family chosen for a parameter is a family its source actually supports. A validator checks that the parameters are dimensioned, in support and inside a permitted family; it cannot check that a Rayleigh is the right shape for that quantity, and parsing the pedigree's prose for a distributional claim is not a check. Review-checklist item **DIST-2** - *"the family and parameterization chosen for this aleatory belief are stated or clearly implied by its cited source, and where they are inferred the inference is in the pedigree"* - lands in `review_signoffs` on the frozen `ExperimentDesign` (ADR-000).
