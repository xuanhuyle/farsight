# ADR-007 — Evidence package format, the registers, and the claim statement
**Status:** Accepted 2026-08-28 (MVP commitment; see Revisit triggers)
**Date:** 2026-08-26
**Deciders:** FarSight founding engineering
**Plan reference:** FARSIGHT_FOUNDATION_PLAN.md §13 (package layout, four registers, audit path), §14 item 9 and trust preconditions, §16 items 1-2, §6 boundary rules, §18 (AT-1, AT-3, AT-6, AT-9); "Things we must get right" items 4 and 7
**Related ADRs:** ADR-000 (the escape-hatch tokens this record's Enforcement uses), ADR-001 (every id in the package is a content hash produced by that scheme, and the `ExperimentDesign` half of `review_signoffs` lives there), ADR-004 (the collapse register is the `EpistemicCollapse` record made auditable), ADR-005 (seed archives are what make `replay` more than a re-run), ADR-006 (tier claims are stamped per run set here, and CC-3/DET-1/GOLD-1 sign-offs land here), ADR-009 (metric and acceptance-rule identity is what `verify` recomputes against), ADR-010 (`FaultActivationRecord` is package content), ADR-011 (the bytes, the `.npy` channels, `channels_manifest.json` and the atomic-write guarantees underneath this layout), ADR-012 (the signing seam attaches to the root hash, and worker logs are deliberately not package content), ADR-013 (the `auditor_boundary` contract is what makes zero-extras verification possible), ADR-014 (the base install `verify` is permitted to need, and the `uv.lock` copy that ships under `environment/`), ADR-015 (`experiment/epoch_labels.json`, the derived index that lets the report show an operator a date without putting a UTC spelling in a hashed document), ADR-019 (Tier-A replay needs the reference container, which is not in the package, and `environment/numeric_environment.json` is what the Tier-A predicate resolves against), ADR-021 (`metrics/comparison_results.json` is package content, and a referent reference resolves to a digest rather than a `name@revision`), ADR-023 (the excluded-run register, the fifth mandatory file under `registers/`), ADR-024 (the CLI verb grammar the audit path is spelled in)

## Context

The evidence package is the product. Everything else in FarSight is machinery for producing one. The forcing question is therefore not "what should we store" but **what must a stranger receive so that, in under two hours, on their own laptop, without trusting us and without installing a simulation engine, they can reach a defensible verdict about a claim we made?**

That question has a specific and hostile audience behind it. §21 contains an audit-usability kill: two consecutive external auditors failing the two-hour audit, or reporting that the package did not increase their trust, kills the format. §21 also contains the 200-line-notebook test, which says the package only has value if the auditability delta over a competent engineer's notebook is worth money. AT-9 makes an external aerospace engineer's written honesty judgement an acceptance criterion. This is one of the few artifacts in the plan whose failure mode is not technical.

Two verified constraints shape the layout. First, verification must run with **zero engine extras installed** (§6, and named in "Things we must get right" item 7 as the most commercially important import rule in the codebase). An auditor cannot be asked to install Basilisk, or to obtain a GMAT application tree, in order to check our arithmetic. Second, the identity scheme cannot be changed once customers hold packages (§16), so the format decisions here are effectively permanent for every package ever shipped.

What breaks if we get this wrong: a package that verifies only on our machines is compliance theater; a package whose prose says something the JSON does not support is a lie with a hash on it; and a package that cannot distinguish "this claim was falsified" from "this claim was too vague to falsify" fails K6 even when every test is green.

## Decision

**1. A package is a directory of files.** Reproduced here because it is the decision:

```
evidence_pkg_<root8>/
  manifest.json                # schema version, package id (= root hash), tool + commit,
                               # tier claims per run set, review sign-offs,
                               # THE CLAIM STATEMENT
  experiment/  experiment_spec.json, matched_config.json, epoch_labels.json   (ADR-015)
  runs/        runspec_<i>.json, seeds_<i>.json, status_<i>.json,
               channels/<i>/<name>.npy, channels/<i>/channels_manifest.json   (ADR-011)
  campaign.json                # master seed, sampling design, JSONL ledger
  inputs/      kernels.manifest.json, reference_data/,
               data/<sha256>            # present only when closure == self_contained
  environment/ fingerprint.json, numeric_environment.json,
               Dockerfile, packages.txt, uv.lock            (ADR-019, ADR-014)
  metrics/     metric_registry.json, metric_results.json, acceptance_results.json,
               sensitivity.json, failure_groups.json, comparison_results.json
  report/      summary.md      # GENERATED from the JSON
  hashes/      file_hashes.json, root_hash.txt, root_hash.txt.minisig (optional)
  registers/   assumptions.json, unknowns.json, collapses.json, validity_violations.json,
               excluded_runs.json   (ADR-023)
  schemas/     *.json          # the JSON Schemas this package was written against
  NOTICES.md                   # NAIF / ISC / Apache / BSD attributions
```

A zip is a *transport container*, never the artifact: zip metadata is not byte-reproducible across tools, so the package identity is always the directory content.

All five registers live together under `registers/`, in one copy each. There is no `experiment/unknowns_ledger.json` mirror: two hash-verified copies of the same data create a precedence question that `verify` would have to answer, and any answer is worse than not having two copies. This is a refinement of plan §13, which shows the unknowns ledger under `experiment/`, names three more registers only in prose, and does not contain the excluded-run register at all (see References).

**2. The root hash is a one-level Merkle root over a flat file manifest.** This is the hash tree §16 item 2 commits to and the Merkle closure §4 describes, kept deliberately one level deep rather than a deep tree. `hashes/file_hashes.json` maps every relative POSIX path to its SHA-256; `root_hash = sha256(JCS(file_hashes.json content))`. An auditor can reproduce this with `sha256sum` and any JCS implementation, which a deep tree cannot claim. Per-run `output_hash` remains the small two-level root over sorted channel hashes plus the metrics document (ADR-001).

**3. The claim statement is a required, structured manifest field.** Not a title, not an abstract: the exact falsifiable sentence, with its falsifier written down.

```json
"claim_statement": {
  "sentence": "At each frozen DSOC pass epoch, the achieved downlink rate is less than or equal to the predicted supportable-rate envelope, within one CCSDS 142.0-B-1 rate-ladder step of its lower edge.",
  "referent_refs": ["<64-hex digest>"],
  "comparator": "achieved_le_predicted_envelope",
  "tolerance_ref": "<64-hex digest of the acceptance criterion>",
  "tier": "B",
  "scope_conditions": ["frozen public pass points only", "no per-pass atmospheric data used"],
  "falsifier": "any frozen point whose achieved rate exceeds the predicted supportable envelope by more than one CCSDS 142.0-B-1 ladder step, i.e. dsoc.rate_ladder_step_delta < -1",
  "evidence_grade": "evidence",
  "partial": false,
  "contains_epistemic_collapse": false
}
```

The falsifier is one-sided because the rule is one-sided: ADR-009's `dsoc.achieved_within_envelope` tests `step_delta >= -1` and nothing in the rule set tests an upper edge, so a two-sided falsifier would name a condition `verify` can never evaluate. A falsifier that cannot be computed from a rule in this package is a sentence, not a falsifier.

Note that the two `tier` fields in a package are different objects. `manifest.tier_claims` stamps what each *run set* achieves in the pinned container (Tier A for the link-chain grid, per ADR-006), while `claim_statement.tier` is the tier the *shipped claim* is made at — Tier B here, because AT-1 scores it by cross-machine replay.

`verify` fails a package whose claim statement lacks a `falsifier` or a resolvable `referent_ref`. "Achieved is close to predicted" is not a claim; it is marketing, and the schema refuses it.

**4. Five registers, each a mandatory file under `registers/`.** An empty register is an assertion that there is nothing to declare; a missing register is a verification failure.

- **Assumption register** (`registers/assumptions.json`): every `Assumption` reachable from the frozen graph, with pedigree and the objects that depend on it.
- **Unknown register** (`registers/unknowns.json`): every flagged unknown with its interval, its source, why it is unknown, and the literal string `"NOT FITTED"`. `verify` cross-checks that no point value for any listed unknown appears anywhere in the package (AT-6). This is the single copy; the plan's `experiment/unknowns_ledger.json` path is superseded by it.
- **Epistemic-collapse register** (`registers/collapses.json`, the "judgment register" of §13): every `EpistemicCollapse` verbatim — original belief, chosen distribution, justification, authorizing human, scope (ADR-004). Any entry sets `contains_epistemic_collapse: true` on downstream verdicts.
- **Validity-violation register** (`registers/validity_violations.json`): every run that exited a declared validity envelope, with the envelope, the excursion, and the affected metric values. Extrapolation happens; it never happens silently.
- **Excluded-run register** (`registers/excluded_runs.json`, ADR-023): every terminal run that is not `ok`, with its outer and inner indices and the criterion that excluded it. This is what a reader needs before they can trust any CDF in the package.

**5. "If prose and JSON disagree, the JSON is the record" is mechanized, not asserted.** `report/summary.md` is produced by a deterministic renderer from package JSON. The manifest records the renderer version and the expected `summary.md` digest; `verify` re-renders and fails on any difference. Hand-edited narrative in a package is therefore impossible, which is a cost we accept deliberately (see Consequences). It is also why worker logs are not package content: a log line carries a wall-clock timestamp and would make byte-equal re-rendering impossible (ADR-012 decides the logging mechanism and states that exclusion as a deliberate cost).

**6. Input closure is declared, and replay is offline by construction.** A package declares `closure: self_contained | referenced_inputs`. `self_contained` embeds every `DataArtifact`'s bytes under `inputs/data/<sha256>` and is **required** for published and pre-registration packages. `referenced_inputs` ships manifests only (kernel metakernel text, per-kernel SHA-256, size, source URL, modified flag) and requires the verifier to supply a local content-addressed cache; every input is resolved by hash and the hash must match the manifest or replay refuses. In both grades the runner and verifier make zero network calls (§16 item 1), which is how AT-1's "any outside-package fetch = fail" is enforced: not by pretending kernels are always embedded, but by forbidding the socket and requiring hash-resolved inputs.

**7. `verify` runs on the base install, with no extras.** Its permitted dependency set is whatever ADR-014's dependency table declares the no-extras base install to be, named by reference and deliberately not copied here: a hand-copied list is exactly how `verify` acquires a dependency nobody decided to give it, and the list is already moving — ADR-022 removed every truth-loop use of SciPy, so SciPy sits in core only for as long as ADR-014 keeps it there and no `verify` code path may be written against it. It never requires the `spice`, `basilisk`, `gmat` or `analysis` extras — in particular `spiceypy`, whose wheel bundles a compiled CSPICE, is an optional extra named `spice` and is never installed by `pip install farsight` (ADR-014 owns the dependency table; see References for the plan amendment this needs). `verify` recomputes every file hash and object hash; validates every document against the JSON Schemas **shipped inside the package**, not the installed ones; recomputes metric values from raw `.npy` channels; checks register completeness and the unknowns invariant; checks reference closure; checks that every applicable review sign-off is present; and exits nonzero naming the exact offending item. It never executes physics. Re-execution is `replay`, a different command with a different trust level and different dependencies.

**8. The audit path is four CLI steps, and step 3 has an install caveat the others do not.** `farsight evidence show` first (claim statement and unknowns register before anything else), then `verify`, then `replay --runs ... --tier A|B` from package content only, then an independent recomputation of one metric from a `.npy` in a plain Python session, plus one referent point checked against its cited public source. `diff` compares two packages structurally. Verb spellings are ADR-024's; this record names the steps, not the grammar. Target: a competent outsider finishes in ≤2 hours.

Steps 1, 2 and 4 run on the zero-extras base install. **Step 3 does not.** `replay` re-executes a run, so it needs the engine that run used: for the flagship link-chain campaign that is FarSight's own `linkchain` package plus, for geometry, the `spice` extra; for a Basilisk run it is the `basilisk` extra; and a Tier-A replay additionally needs the reference container image, which is not package content (ADR-019). The two-hour audit path is therefore a *verification* path for a stranger with one install, and a *re-execution* path only for someone who takes a second install step and obtains an image. We say this here rather than let an auditor discover it at step 3, and it is carried into Forecloses rather than left as a footnote. No web UI exists, in MVP or in the roadmap.

**9. Review sign-offs are package content, not a norm.** Several rules in this set cannot be mechanized and substitute a named review checklist item (ADR-000's `NOT MECHANIZABLE:` and `PARTIALLY MECHANIZED:` tokens mark every one). A checklist item with no record is a norm, and norms are not auditable. The manifest therefore carries:

```json
"review_signoffs": [
  {"checklist_item_id": "EV-1", "reviewer": "<human identity>", "date": "<date>",
   "statement": "one sentence recording what was checked"}
]
```

`checklist_item_id` is drawn from a closed registry held in one place, `src/farsight/evidence/checklist_registry.py`, whose contents are asserted against this set by `adr-lint`: PROC-1 (ADR-000); PREC-1, FREEZE-1 (ADR-001); WORKER-1 (ADR-002); PHYS-1 (ADR-003); UNC-1, COLLAPSE-1, PRES-1 (ADR-004); SEED-1 (ADR-005); CC-3, DET-1, GOLD-1 (ADR-006); EV-1, UNK-1 (here); NUM-1 (ADR-008); METRIC-PURE-1, TOLERANCE-CHANGE (ADR-009); FAULT-BOUNDARY, FAULT-AST (ADR-010); STORE-1 (ADR-011); LOG-CONTENT, NET-1 (ADR-012); BOUNDARY-1 (ADR-013); FIXTURE-1 (ADR-014); TIME-1 (ADR-015); KERN-1, KERN-2 (ADR-016); TOPO-1, TOPO-2 (ADR-017); COMPOSE-1 (ADR-018); ENV-2, ENV-3 (ADR-019); CHAN-1 (ADR-020); REF-1, REF-2, REF-3 (ADR-021); DIST-1, DIST-2 (ADR-022); DIV-1 (ADR-023); CLI-1, CLI-2 (ADR-024); LLM-1 (ADR-025). `verify` fails any `evidence_grade: evidence` package missing a row for an item its content makes applicable. The `ExperimentDesign` carries the same field for design-time items (ADR-001). What a human answered cannot be checked; that a named human answered it, on a date, inside a hashed document, is entirely checkable, and that is the whole of what this field claims.

## Options considered

### Option 1 — Directory of plain files plus a flat hash manifest — CHOSEN
Every artifact is independently openable, independently hashable, and independently checkable with tools the auditor already trusts. The format degrades gracefully: even with FarSight gone, the JSON and the `.npy` files remain readable.

### Option 2 — Single zip or OCI artifact as the package identity — REJECTED
One file to email, one digest to sign, and a content-addressed registry would do distribution for us. The strongest form is not a naive zip: reproducible zip is a solved problem (fixed mtimes, sorted entries, pinned compression, as the Debian, Bazel and Python wheel ecosystems all rely on), and an OCI artifact has a spec-defined content-addressed digest plus layer dedup that would give us exactly the cross-package input sharing this record's Forecloses admits it loses. So the rejection cannot rest on "zip bytes are not reproducible". It rests on two things that survive. First, partial verification: AT-3 requires a flipped byte to fail loudly **and name the item**, and naming one file inside an archive means unpacking the archive first, so the tamper story becomes a story about our unpacker. Second, the auditor's first move: `sha256sum` on a file they can already see beats any unpacking step, and the two-hour budget is spent on trust, not on tooling. Reproducible zip remains available as a *transport* wrapper, which is how we use it.

### Option 3 — SQLite file as the package — REJECTED
A single transactional file, queryable, with one hash and no directory-walk semantics. Genuinely attractive for a 10k-run campaign with many small documents. Rejected because it puts a storage engine inside the trust surface: the auditor must run our schema's SQL to see anything, a channel stops being "one line of NumPy", and a corrupted page fails the whole package rather than naming one item (AT-3 requires naming the item).

### Option 4 — Assurance-case argument model, GSN / AdvoCATE style — REJECTED for MVP
This is the closest institutional prior art and the option with the strongest claim on the audience we are aiming at. The steelman is not "replace files with a document" and it is not "narrated rather than checked": GSN has a standardized machine-readable interchange form, assurance-case tooling performs automated well-formedness and completeness checking on the argument graph, and mission-assurance reviewers are trained to read exactly this shape. The strongest version keeps the hash-rooted file package exactly as specified here and makes an argument graph the *top-level organizing artifact*, with the claim statement as the top goal and the five registers as its leaves. That is a real option and the machine-verifiability objection against it is false; we state that plainly rather than reject it on a claim a reviewer would catch. Rejected on scope and sequencing: an argument graph is a second schema, a second validator and a second review burden inside an eight-week build, and it presupposes an argument structure we have not earned before the week-8 auditor tells us what they actually read. The registers plus the claim statement preserve the option at zero cost — a GSN view can be generated later without changing the record.

### Option 5 — Hosted evidence with a permalink — REJECTED
Trivial sharing, live re-verification, usage analytics. Rejected outright: it violates offline-first (§16), puts FarSight permanently in the trust path, and makes every published claim depend on our continued existence and uptime. An evidence artifact that dies when the vendor dies is not evidence.

## Consequences

**Buys us:** verification on an auditor's laptop with zero engine extras; tamper evidence that names the exact file; a falsifiable claim as a schema-enforced field rather than a habit; a format that survives the company; the five registers as a standing answer to "what did you assume, what did you not know, where did you exercise judgement, where did you extrapolate, and what did you not count"; and, through `review_signoffs`, the set's human-judgement escape hatches converted from norms into rows a stranger can count.

**Costs us:** packages are large, because channels dominate and self-contained packages re-embed kernel bytes. Building a package can be blocked by paperwork, since a missing pedigree, an unbounded `Unknown` or a missing sign-off fails the freeze that precedes it. Every schema change requires an archived-fixture reader kept alive forever. And the generated-report rule means a customer who wants to add narrative commentary to their own evidence package cannot: commentary must go in `scope_conditions` and register entries, or outside the package entirely. That will be an early complaint and we are choosing to take it.

**A claim may cite other packages by root hash.** The closure rule above says a package is closed and self-contained; it does not say a package is unaware of others. A `claim_statement` may name other packages' root hashes as cited evidence — which is how a cross-vintage kernel comparison, a cross-fidelity validation (ADR-021 decision 8a) or, later, a scenario-matrix study over many campaigns states a conclusion that spans campaigns: **the cross-campaign claim is itself a package, whose inputs are other packages' root hashes.** This generalizes the supersession idiom ADR-011 already uses and costs nothing now, because a root hash is a 64-hex string in a document that already exists. What it deliberately does not create is a "study series" object linking a design to the design that motivated it. If that link is ever wanted it belongs in the *unhashed* provenance block, which ADR-001 keeps outside identity: a hashed back-link would make a design's identity depend on its own search history, so that a design reached by a different route would hash differently while being the same experiment.

**Forecloses:** incremental or streaming packages. A package is closed at build time and its root hash covers the closed set; there is no "append run 10,001 to the shipped package", only a new package. It forecloses cross-package deduplication of shared inputs, so ten self-contained packages over the same Psyche kernels carry ten copies. Because `verify` may never import an engine, verification can never re-derive physics: it recomputes metrics from stored channels only, which means a package whose channels are wrong but internally consistent will verify. And it forecloses the sentence we would most like to say about the audit path: **a zero-extras auditor gets `show`, `verify`, `diff` and an independent metric recomputation, and cannot run `replay` at all.** Step 3 needs the run's engine extras and, at Tier A, a container image the package does not contain. Anyone who has not installed FarSight's own engine code is on a verification path, not a re-execution path, and every external description of the audit must say so. A second, narrower foreclosure sits behind `verify`'s metric recomputation: the package ships a metric's declarative definition and two hashes of the implementation, not the implementation, so recomputation is a self-consistency check against the *installed* FarSight version rather than against the version that produced the package (ADR-009).

## Enforcement

1. CI job `auditor-install` (defined in ADR-013, every commit; **first green by week 4**, when the first fixture package exists): creates a clean virtualenv, installs `farsight` with **no** extras, and runs `farsight evidence verify` against the archived fixture packages under an import hook that fails the job if `bsk`, `Basilisk` or `spiceypy` is imported at any point. This ADR contributes the fixture corpus; the job is defined once, in ADR-013.
2. import-linter contract `auditor_boundary` (defined in ADR-013; **first green by week 1**): `farsight.evidence` and `farsight.hashing` may not import `farsight.engines` or any optional-extra distribution. This record does not restate the rule or its rationale; it consumes it.
3. `test_tamper_matrix` (AT-3; **first green by week 4**): programmatically flips one byte in each file class (a channel `.npy`, a kernel manifest entry, a `seeds_<i>.json`, a metric version string, `file_hashes.json` itself) and asserts `verify` exits nonzero and prints the offending path. A pass on mutated evidence fails the build.
4. Manifest schema validation (**first green by week 4**): `claim_statement` with an empty `sentence`, a missing `falsifier`, or an unresolvable `referent_ref` fails verification; a package missing any of the five register files fails verification; `evidence_grade: evidence` combined with an unattended freeze, with a collapse-register entry not carrying an authorizing human, or with a missing applicable `review_signoffs` row fails verification.
5. PARTIALLY MECHANIZED: `test_unknowns_invariant` (AT-6; **first green by week 4**). The package half is mechanical and stays: for every entry in the unknown register, assert that no point value for that parameter path appears anywhere in the package. The codebase half of AT-6 — "no default for it exists in the codebase" — asks a test to prove a universal negative about arbitrary source, and it is not decidable: a default may be a literal, a dict entry, a fallback in an adapter, or a value computed at import. It is replaced by a bounded lint: no numeric literal in `src/farsight/` may match, to full precision, a value listed in the unknown register of any archived fixture package. Residue: a default expressed as an expression, a lookup, or a value not in any fixture register is invisible to the lint. Review checklist item **UNK-1** — "the parameter has no default anywhere in the code path that would be taken if the operator omitted it" — carries the residue, and a UNK-1 row lands in `review_signoffs` for every `evidence_grade` package whose unknown register is non-empty.
6. `test_report_render_determinism` (**first green by week 4**): re-render `report/summary.md` from package JSON and assert byte equality with the recorded digest; this is the "JSON is the record" rule in mechanical form.
7. `test_package_reader_compat` (nightly): verify archived packages from every prior schema version using their embedded schemas, proving old packages verify forever (ADR-011 migration-on-read policy). **First green by week 4 in its one-version form, where it is close to vacuous.** It becomes load-bearing only when a second `schema_version` exists, which is not planned inside the MVP; saying it protects us before then would be a claim about a test with one fixture.
8. NOT MECHANIZABLE: whether a claim sentence is *honest* rather than merely well-formed. Review checklist item **EV-1** — "the claim statement names what observation would refute it, and a reader who disagrees with us would accept the falsifier" — is a second-developer sign-off, and it is required before any package is marked `evidence_grade`. What is mechanized is the row: an `evidence_grade` package with no EV-1 entry in `review_signoffs` fails verification (item 4). AT-9 makes an external engineer's written judgement the backstop for the content.
9. `test_review_signoffs` (unit tier; **first green by week 4**): asserts that every `checklist_item_id` in a package resolves to the closed registry in `src/farsight/evidence/checklist_registry.py`, that each row carries a non-empty reviewer and date, and that an `evidence_grade` package containing a Tier-C comparison, a non-empty unknown register, or a collapse-register entry carries the corresponding CC-3, UNK-1 or judgement row. This is the mechanical half of every escape hatch in the set.
