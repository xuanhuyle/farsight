# ADR-020 — Channels: name grammar, sample grid, and metadata
**Status:** Accepted 2026-08-28 (MVP commitment; see Revisit triggers)
**Date:** 2026-08-26
**Deciders:** FarSight founding engineering
**Plan reference:** FARSIGHT_FOUNDATION_PLAN.md §7 (canonical channel bytes and the `(name, unit, dtype, shape)` header), §13 (`runs/channels/<i>/<name>.npy`), §12 (Tier-B comparison at defined epochs), §4 (`ScenarioTemplate` epoch span), §17 weeks 3-4 (first link-chain output and first metric)
**Related ADRs:** ADR-017 (the naming authority; a channel name is a topology path plus a leaf, and its path grammar is this record's grammar), ADR-011 (owns the channel header and the `.npy` record this record adds one field to), ADR-009 (a metric's channel inputs and its "lowest sample index" first violation resolve against this grid), ADR-006 (Tier-B comparison epochs become indices into this grid), ADR-010 (the predicate evaluation cadence, and the code map that lets a predicate compare a channel to a named state), ADR-015 (owns the epoch representation of the grid's `epoch0`, consumed here and not defined), ADR-018 (qualifies channel names with a stage id, and delegates the grammar of both halves here), ADR-021 (referent epoch alignment against this grid), ADR-008 (unit strings and the sample axis every reduction runs over), ADR-001 (the grid descriptor is a hashed document, so it contains no JSON floats), ADR-023 (the outcome of a run whose channels stop short of the grid)

## Context

Week 3-4 produces the first link-chain output and the first metric, and at that moment three accepted records make demands that no record satisfies. ADR-009's `MetricContext` hands a metric `channels: Mapping[str, np.ndarray]` and evaluates a domain predicate elementwise across several of them, which presupposes a shared index. ADR-006 requires Tier-B comparison "at defined comparison epochs". ADR-010 evaluates fault predicates on a declared cadence and records which sample fired. ADR-009 defines "first violation" as the lowest sample index. **Nothing anywhere says how sample index *i* becomes a time.**

The second gap is the name. The set is already internally inconsistent about what a channel is called: `pt_over_n0` with no namespace (ADR-006, ADR-011), `link.margin` and `geometry.in_view` with one (ADR-009), and `link.supportable_rate_bps` with a unit suffix baked into the name (ADR-009) — a convention ADR-008 adopts deliberately, but only *inside* the raw-float core where no metadata exists. Channel names are not free-floating labels: they are keys in hashed metric definitions, entries in `hashes/file_hashes.json`, and — because ADR-011 stores one `.npy` per channel at `channels/<i>/<name>.npy` — **filenames**. Two names differing only in case are one file on Windows and two on Linux, which surfaces as a Tier-B divergence that reads like a physics bug, and a channel named `con` or `nul` cannot be written on Windows at all.

The third is a correctness hole in the tamper-evidence claim. ADR-011 hashes a channel as `sha256(JCS(header) || payload)` with `header = {name, unit, dtype, shape}`. The sample grid is not in that header. A channel computed on a 60-second grid and a channel computed on a 10-second grid, truncated to the same length, hash identically if their values happen to match — and more practically, a run re-executed against a different time base produces a channel that **hash-verifies clean**. ADR-011 states the hole and says this record closes it.

What breaks if this is wrong: channel names live in hashed metric definitions and in the referent-comparison metrics, so renaming after the DSN anchor ships is a re-golding of every metric; and a grid that is not in the hash means AT-3's tamper matrix has a class of mutation it cannot see.

## Decision

**1. A channel name is a topology path plus a leaf.** The grammar is ADR-017's, unchanged and not restated: lowercase ASCII segments, dot-separated, at most 7 segments and 64 characters, no indices, no wildcards, no Windows reserved device name in any segment. A channel name has at least two segments. Its prefix must resolve to a node in the run's `SystemTopology`, and its final segment is the `ChannelDecl.name` local to that node, disjoint from that node's child names and parameter names.

There is **exactly one reserved namespace that is not resolved against the topology**: `run`. `run` is forbidden as a topology node name (ADR-017), and the only names admissible under it are the ones this record enumerates. Today that is one: `run.t_elapsed`, which the runner writes rather than any stage. An engine diagnostic that belongs to no node is not a channel; it goes in the engine manifest that `collect()` returns (ADR-003).

**The qualifier is the stage id, and a stage id is a node path.** ADR-018 composes a run from ordered stages, qualifies each stage's emitted channel names with its `stage_id`, and delegates the grammar of both halves to this record. The grammar is: **a `stage_id` must be a node path in the run's topology**, and a stage's `emits` entries are channel paths *relative to that node*, so the run-level channel name is `stage_id + "." + emitted name` and resolves as a topology path by construction. ADR-018's uniqueness rule needs one addition to stay true under relative emits: **the stage nodes of a run must be pairwise non-overlapping** — no stage's node may equal or be an ancestor of another's — which makes a collision between two stages' qualified names impossible rather than unlikely. A geometry stage named `geometry` emitting `range` and `in_view` produces `geometry.range` and `geometry.in_view`; a link stage named `link` produces `link.margin`. Those are exactly the spellings ADR-009's examples already use.

The first segment is therefore a name the customer chose, not a category we defined. There is no closed list of namespaces such as `link`, `geometry`, `power` — that list would be a physics ontology in the one place it is easiest to smuggle one in (ADR-017, plan §2 tripwire 1). `link.margin` is legal because the author declared a node called `link`, and `geometry.in_view` because they declared one called `geometry`.

**A unit may not appear in the name.** `link.supportable_rate_bps` becomes `link.supportable_rate` with `unit: "bit/s"` in its declaration; `pt_over_n0` becomes `link.pt_over_n0`, which needs a namespace but keeps its name, because `n0` is a physical symbol and not a unit. The reason is not tidiness: the unit is already declared, already hashed, and already carried in the header, so a suffix is a second declaration that nothing checks against the first, and the failure mode is a name that says `_db` over an array in linear ratio.

**2. A `ChannelDecl` is knowledge-plane, and it sits on the node** (ADR-017 owns the model; reproduced here because the fields are this record's decision):

```python
class ChannelDecl(BaseModel):        # frozen=True, extra="forbid"
    name: str                        # local segment; full path is <node path>.<name>
    unit: str                        # astropy-parseable; "1" for dimensionless
    components: int = 1              # trailing axis width; 1 means a scalar channel
    component_labels: list[str] | None = None   # optional; names the entities on that axis
    code_map: dict[str, int] | None = None
    description: str
    conforms_to: str | None = None   # optional ObservableDef digest (ADR-028)
```

It is knowledge-plane rather than design-plane because ADR-010's `FaultMode.detection: list[ObservableRef]` is a knowledge-plane object that names channels, and a knowledge-plane record may not reference a design-plane one.

**Every channel is `<f8` little-endian float64, C-order, and axis 0 is always the sample axis.** There are no integer, boolean or string channels. Shape is `(n, )` for `components == 1` and `(n, components)` otherwise, and `n` is the same for every channel of a run (decision 4). The sample axis being axis 0 by rule is what makes ADR-009's "lowest sample index" and ADR-008's ordered reductions well defined without either record having to guess.

**A declaration never restates something already hashed elsewhere.** ADR-015 needs a channel of geometric range to be distinguishable from one of apparent range, and says the label travels in channel metadata. It travels in `description`, and the *authoritative* record stays where it already is: the producing stage's hashed `GeometryRequest.aberration` (ADR-015, ADR-018). This is the same rule as the unit-suffix ban one paragraph up, applied to a second case — a second, independently authored label can disagree with the config that actually produced the numbers, and nothing would catch it. `ChannelDecl` therefore acquires no field for aberration, for frame, or for any other production convention.

**Categorical channels carry a `code_map`.** ADR-010's predicate grammar compares `{"channel": "gnc.pointing_mode"}` to `{"const": "safe"}` — a string compared to a float64 array, which is not evaluable as written. A channel declaring `code_map: {"safe": 2, "science": 3}` resolves that comparison at compile time to an exact numeric equality. Codes are integers in `[-2**53, 2**53]`, so equality against a code is exact in float64 rather than a floating-point comparison in disguise, and that bound is validated. A channel with a `code_map` may appear only in equality and inequality comparisons and as a domain gate; it may not be a reduction operand, because the minimum of a set of codes is not a quantity.

**The trailing axis is where per-entity state lives, and `component_labels` names it.** A swarm of a thousand relays does not become a thousand channels, a thousand nodes or a thousand files: it is one `ChannelDecl` with `components: 1000` on the node that denotes the swarm, and per-entity state is a column. This keeps file count linear in *channels* rather than in entities, which is the property that makes system-of-systems campaigns storable at all (ADR-011). The axis is anonymous unless declared: `component_labels`, when present, has exactly `components` entries in segment grammar, and it is what lets an auditor say which relay column 42 is and join it to a fault record naming that relay. Labels are display and join metadata only — never parsed for meaning, never dispatched on, in keeping with ADR-017 rule 7 — and a channel whose columns are an unordered ensemble sample legitimately leaves them absent. Note the deliberate asymmetry with names: `ObservableRef`s and predicate leaves address *channels*, never components, because ADR-017's grammar admits no indices; a metric that needs one entity's series needs that entity to be a node, which is the point at which the modelling granularity should be reconsidered rather than the grammar.

**Entity absence is a code, never a non-finite.** In any campaign with attrition, staggered deployment or dormancy, some entities do not exist for part of the grid — a relay not yet launched, a probe dead at year 12. The sanctioned encoding is a lifecycle channel with a `code_map` (`{"unlaunched": 0, "cruise": 1, "dormant": 2, "active": 3, "dead": 4}`) plus a physical channel that holds its last value or zero; the lifecycle channel then gates metrics as a domain and gates predicates as an equality. **NaN is not an absence marker.** ADR-023 makes any non-finite sample a divergence, so an engine that writes NaN into a dead entity's column marks the entire run `diverged`, excludes it from realized aggregation and pushes verdicts toward `indeterminate` — precisely for the runs in which the attrition physics worked as designed. That interaction is invisible until a Stage-5 campaign produces an all-`indeterminate` result for no discoverable reason, which is why the convention is written here rather than discovered there.

**3. The frozen design declares which channels a run must produce.** `ScenarioTemplate.emitted_channels: list[str]`, byte-wise sorted, each resolving to a `ChannelDecl` under an active subtree (ADR-017), plus the mandatory `run.t_elapsed`. A run whose `collect()` returns a channel not on that list, or omits one that is, fails naming the channel. Refusal lands at freeze where it can (an unresolvable name) and at collect where it cannot (an adapter that did not emit what it promised) — the same freeze-first preference ADR-003 states.

**4. One sample grid per run, shared by every channel, declared in the frozen design, and never interpolated.**

```jsonc
"sample_grid": {                       // hashed; no JSON floats (ADR-001).
  "kind": "uniform",                   // Values illustrative, not a commitment.
  "epoch0": { /* ADR-015 owns this representation */ },
  "step": {"magnitude": "60", "unit": "s"},
  "n_samples": 8640
}
// or
"sample_grid": {"kind": "explicit", "epochs_artifact": "<64-hex digest>"}
```

`epoch0` is an ADR-015 `Epoch` and nothing else; `uniform` is the ordinary case, where sample *i* sits at `epoch0` advanced by `i * step` computed in ADR-015's exact epoch arithmetic from the decimal-string step, never by accumulating a float. `explicit` covers a grid that is not uniform — pass-scheduled sampling, for instance — by referencing a hash-pinned `DataArtifact` of epochs that ships in `inputs/` (ADR-007) rather than embedding thousands of numbers in a hashed JSON document.

**The grid descriptor is a hashed document in its own right, and its digest is the grid's identity.** `grid_hash = sha256(JCS(sample_grid)).hexdigest()` — 64 lowercase hex characters with no algorithm prefix, the one spelling ADR-001 decision 7 admits inside a hashed document — is what ADR-018's `StageSpec.grid` and ADR-015's `GeometryRequest.epochs` reference, both of which are `Ref`-shaped and therefore admit only a digest (ADR-001 rule 7). It is also the field decision 6 binds into every channel header, so the same digest names the grid in the design, in the geometry request, in the stage list and in the hash of every array produced against it.

The grid is **fixed by the frozen design and identical across every run of an experiment**, and every stage of a run references that one grid. This is strictly stronger than ADR-018's composition rule 4, which requires equal grids only where a channel flows from one stage to another, and it subsumes it: ADR-009's metrics consume channels from different stages in one elementwise expression — `geometry.in_view` gating `link.margin` is its own worked example — so equality only along binding edges is not enough. A grid field may not be a `Belief`. Cadence is therefore not an epistemic coordinate and not a swept parameter; a convergence study over cadence is N experiments. That restriction is what lets ADR-004's p-box, ADR-009's aggregates and ADR-006's Tier-B comparisons index runs against each other elementwise without anyone interpolating.

**No interpolation exists anywhere in the truth loop.** A Tier-B comparison epoch is either a grid index or an epoch that must match a grid sample exactly, checked at freeze; a referent point whose epoch is not on the grid is ADR-021's problem to align and is never resampled here. ADR-010's predicate `evaluation_period` must be the grid itself or a decimation of it by a declared integer stride, so "which sample fired" is an index into the same axis every other record counts on.

**5. `run.t_elapsed` is mandatory, and it is derived, not authoritative.** It is a float64 channel in seconds elapsed from `epoch0`, with `t_elapsed[0]` exactly `0.0`. It exists so that an auditor in a plain Python session can read epochs with one line of NumPy, which the descriptor cannot offer because expanding it needs ADR-015's arithmetic. It deliberately carries *elapsed seconds*, not an absolute epoch: a float64 cannot hold ADR-015's epoch representation without a precision claim this record has no business making, and elapsed seconds over a mission arc are exact to well under a microsecond. `farsight evidence verify` re-expands the descriptor and fails on any difference from the stored `run.t_elapsed`, so the two cannot disagree.

**6. The sample grid enters the channel hash.** ADR-011's header gains exactly one field:

```python
grid_hash = sha256(JCS(sample_grid)).hexdigest()   # bare 64-hex; no algorithm prefix (ADR-001)
header = {"name": "link.pt_over_n0", "unit": "dB", "dtype": "<f8",
          "shape": [8640], "grid_hash": grid_hash}
channel_hash = sha256(JCS(header).encode("utf-8") + b"\x00" + array.tobytes(order="C"))
```

This is the whole of the fix for the hole ADR-011 names, and it is one field because one field is enough: the descriptor is small, exact and already hashed as part of the design, so binding its digest into every channel makes "computed on a different time base" a hash difference rather than a silent pass. `channels_manifest.json` records `grid_hash` alongside the fields ADR-011 already lists. Every channel hash in the set therefore differs from what a reader of ADR-011's four-field example would compute, which is stated plainly because that example appears in an accepted-track record.

**7. Filenames.** A channel is written to `channels/<i>/<name>.npy` using the channel name verbatim, dots included. Three properties make that safe and they are all consequences of ADR-017's grammar rather than new rules: lowercase-only means no case-collision between a Windows and a Linux run; the reserved-device-name ban applies to every segment, so `con.margin.npy` cannot be authored; and the 64-character cap keeps the package-relative path near 90 characters, leaving room under the legacy 260-character Windows limit for an auditor's own extraction directory. A channel name is never transformed on its way to a filename — no escaping, no hashing, no case folding — so the mapping is a `.npy` suffix and nothing else, and `file_hashes.json` paths are readable.

**8. A run that stops early truncates every channel to the same index.** If a run terminates before the grid is exhausted, all of its channels have `shape[0] == k` for one `k`, `channels_manifest.json` records `samples_written: k`, and the grid descriptor is unchanged, because the grid is a declared input and not a report of what happened. Such a run cannot be `ok`; which outcome it takes and whether it participates in an aggregate are ADR-023's decisions.

**Review sign-offs are records, not norms.** The residue below (CHAN-1) is a row in the `review_signoffs` field on the frozen `ExperimentDesign` and `EvidencePackage` (ADR-000).

## Options considered

### Option 1 — Free-form channel names with a house convention — REJECTED
What every simulation output already does, and what the drafts of this set did: Basilisk names recorded messages after modules, and `pt_over_n0` is a perfectly clear name to a link engineer. Zero schema, zero authoring cost, and no coupling between output naming and the knowledge plane. Rejected because a name that nothing validates is a name that eventually collides with a filesystem: the Windows case and reserved-device hazards are not hypothetical, and the set had already produced four mutually inconsistent naming styles across five records before anyone wrote a line of code. It also leaves ADR-010's `detection: list[ObservableRef]` pointing at strings nothing can resolve, so a fault mode citing an observable that does not exist freezes cleanly.

### Option 2 — Opaque channel ids with a lookup table in the manifest — REJECTED
Renaming becomes free, filenames become trivially safe, and the id is stable across every rename a customer will inevitably want. Rejected for the same reason ADR-017 rejects surrogate paths and it is the same argument: `channels/4242/a3f2c1d0.npy` teaches an auditor nothing, and §13's two-hour audit path plus §7's "hashing the file is hashing the numbers" both assume a human can see what they are holding.

### Option 3 — A closed FarSight namespace list (`geometry.`, `link.`, `power.`, `attitude.`) — REJECTED
Attractive because it would make metric definitions portable across missions without any topology agreement, and because a fixed vocabulary is what a metric library wants. Rejected because it is a physics ontology with a smaller word count: the moment we ship the list, we own the question of which namespace a laser terminal's detector chain belongs in, for every customer, forever. Plan §2 refuses that, and ADR-017's answer — the customer names their own nodes and FarSight never dispatches on the name — costs us metric portability instead, which is named in Forecloses.

### Option 4 — Per-channel independent grids, with metrics resampling as needed — REJECTED
This is the strongest rejected option and it is what every serious time-series stack does: engines genuinely produce different natural cadences, an attitude channel at 10 Hz alongside a per-pass link channel is the honest shape of the data, and forcing one grid means either upsampling cheap channels or wasting samples on expensive ones. Libraries to align and resample such data are mature and standard. Rejected on three grounds that survive that. Resampling is interpolation, interpolation is physics, and plan §2 says FarSight never reimplements physics an engine provides — an interpolation kernel chosen by our metric layer would be an unstated model sitting between the engine's output and the customer's verdict. "First violation at the lowest sample index" (ADR-009) and "which sample the predicate fired on" (ADR-010) become ill-defined the moment there is more than one index. And a metric's value would depend on a kernel nobody declared, which is exactly the class of hidden choice this product exists to eliminate. The honest alternative is available and cheaper: different cadences are different run sets, compared at declared epochs.

### Option 5 — A mandatory time channel and no descriptor — REJECTED
One array, no second representation, and non-uniform grids need no special case. Genuinely simpler. Rejected because a channel is *produced by a run*, so the grid would be an output rather than a frozen input: nothing could validate a comparison epoch or a predicate cadence at freeze, and a run that silently used a different time base would be discovered, if at all, by someone reading numbers. It also cannot enter a hashed spec, since a float64 array is not admissible in a document ADR-001 governs. The descriptor is what makes the grid a declared input; the channel is what makes it readable.

### Option 6 — A descriptor and no materialized time channel — REJECTED
No redundancy, and the descriptor is authoritative anyway. Rejected on the audit path: expanding `epoch0 + i * step` requires ADR-015's epoch arithmetic, which the auditor in a plain Python session does not have, and step 4 of ADR-007's audit path is precisely "independently recompute one metric from a `.npy` in a plain Python session". Keeping both, with `verify` asserting they agree, costs one array per run and buys the one thing the audit path needs.

### Option 7 — Topology-rooted names, one declared grid, grid in the channel hash — CHOSEN
Accepts a coupling between channel naming and the knowledge plane, and a hard refusal to interpolate, in exchange for names that resolve, files that write on both platforms, and a channel hash that means what the tamper-evidence claim says it means.

## Consequences

**Buys us:** a channel name that resolves to a declaration, so a metric input, a fault observable and a file path are all checkable at freeze; one index shared by every channel, which is what makes "first violation", "the sample the predicate fired on" and "comparison at defined epochs" the same axis; a channel hash that detects a changed time base, closing a hole that would otherwise have made AT-3's tamper matrix incomplete in a way an auditor could find; and filenames that are safe on Windows by construction rather than by care.

**Costs us:** adding a channel is a topology edit, and therefore a knowledge-plane re-hash, a design re-hash and a new `experiment_hash`. The first time someone wants a one-off debug trace this will feel absurd, and the sanctioned answer — declare the node and the channel, or put it in the engine manifest — is more ceremony than a `print`. Channel names now carry a customer's naming convention into every metric definition. `run.t_elapsed` is one more array per run at eight bytes per sample, on top of a design ADR-011 already says has no compression anywhere. And the code map is a hashed commitment, so adding a new mode code to a categorical channel re-hashes the topology.

**Forecloses:** interpolation, permanently and by construction. A referent point whose epoch is not on the grid cannot be compared by resampling — the DSOC pass epochs have to be designed into the grid in week 3, before the campaign runs, and discovering a needed epoch in week 7 means a new experiment rather than a new query. Cadence can never be an epistemic coordinate or a swept parameter, so "does the answer depend on sample rate" is N experiments and N sets of hashes rather than one campaign.

It forecloses non-float channels forever. There are no integer counters, no boolean flags, no string state channels and no ragged or event-list channels; an event that happens at an irregular time is either a code channel on the grid or it is not a channel. A campaign that wants to record 12 discrete fault-clearing events records them in `FaultActivationRecord` (ADR-010), never as data.

And it forecloses portable metric libraries. Because a channel name embeds the customer's node names, a metric definition is reusable only across topologies that agree on those names. Two customers computing the same link margin will hold two metric definitions with two identities, and FarSight will not ship the vocabulary that would have unified them, because shipping it is shipping an ontology.

## Enforcement

1. **`test_channel_name_grammar`** (unit tier, every commit, Windows and Linux; **first green by week 1**): every declared channel name parses under ADR-017's grammar, has at least two segments, resolves to a `ChannelDecl` in the run's topology or is the enumerated `run.t_elapsed`, and contains no Windows reserved device name in any segment. It also fails a leaf segment ending in a unit token from an explicit denylist (`_db`, `_bps`, `_hz`, `_m`, `_km`, `_s`, `_w`, `_rad`, `_deg`, `_au`, `_k`, and the rest of the list held in the test).
2. **`test_channel_filename_safety`** (**first green by week 2**, Windows and Linux legs): writes and reads back the whole fixture channel set on both platforms; asserts that no two declared names of one run collide under case folding, that every package-relative channel path is under the stated budget, and that a deliberately malformed name (`CON.margin`, `link.Margin`, a 200-character name) is rejected by the validator before any file is opened.
3. **`test_sample_grid_in_channel_hash`** (**first green by week 1**): two channels with byte-identical payloads, identical names, units, dtypes and shapes, and different `sample_grid` descriptors must produce different `channel_hash` values; and mutating one character of the descriptor must change `grid_hash`. This is the mechanical form of the hole ADR-011 names.
4. **Freeze validator `channels_declared_and_resolvable`** (**first green by week 2**, with the `design` schema pack): every entry of `emitted_channels`, every metric channel input, every `ObservableRef` and every predicate channel leaf resolves to a `ChannelDecl` under an active subtree; `run.t_elapsed` is present; a name that resolves to a node or a parameter rather than a channel fails naming the path. It also enforces the qualifier rule: every ADR-018 `stage_id` resolves to a node path, the stage nodes of a run are pairwise non-overlapping, and every `emits` entry resolves relative to its own stage node.
5. **`test_single_sample_grid`** (**first green by week 2**): a `RunOutput` whose channels do not all share `shape[0]`, or whose declared `components` disagrees with the trailing axis, or which contains a channel not on the frozen `emitted_channels` list, fails collection naming the channel. A run truncated at *k* samples must be truncated in every channel.
6. **`test_grid_materialization`** (**first green by week 4**, with the single-run package v0): re-expanding the `sample_grid` descriptor reproduces `run.t_elapsed` bitwise, `t_elapsed[0]` is exactly `0.0`, and `farsight evidence verify` (defined in ADR-007) exits nonzero naming the run when it does not.
7. **`test_channel_code_map`** (**first green by week 5**, when the predicate compiler exists): a predicate comparing a channel to a string constant compiles only if that channel declares a `code_map` containing the constant; every code is an integer within the exactly-representable float64 range; and a code-mapped channel used as a reduction operand fails compilation naming the metric.
8. **`test_tamper_matrix`** (defined in ADR-007; **first green by week 4**): this record contributes one case to that matrix — mutate the `sample_grid` descriptor alone, leaving every channel byte untouched, and assert `verify` exits nonzero naming the item. Without decision 6 that case passes, which is the whole reason the field exists.
9. **PARTIALLY MECHANIZED: CHAN-1** (**first green by week 1** for the mechanical half) — whether a channel's declared unit is the unit its producer actually computes in. Mechanically: the `unit` string parses under astropy (ADR-008), it matches the `ChannelDecl`, the header carries it into the hash, and the name-suffix denylist in item 1 catches the common way a second, contradictory unit claim gets attached. What no check can do is compare a declared unit against the arithmetic that filled the array — a link margin computed as a linear ratio and declared `dB` is well-formed at every boundary we control, and it is exactly the missing-term class plan §19 risk 2 says a domain reviewer will find first. Review-checklist item **CHAN-1** — *"the channel's declared unit is the unit its producer computes in, and its name does not restate a unit"* — carries the residue and lands in `review_signoffs` for the release that introduces or changes a channel declaration.
10. **`test_channel_roundtrip`** (defined in ADR-011; **first green by week 1**): the header this record extends is hashed there, and that job asserts platform and NumPy-patch invariance of `channel_hash`. This record adds the field, not a second test of the same property.
